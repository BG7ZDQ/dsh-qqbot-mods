# 04 · 修复记录（踩坑与解法）

以下都是实际遇到并修掉的问题，按"现象 → 原因 → 解法"记录。

## 1. 工具调用报 `ToolTimeoutError: TOOL_TIMEOUT`

- 现象：`glob` 等工具在群里调用直接超时，机器人只能回一句报错。
- 原因：插件工作目录默认在用户主目录，`glob` 扫描过快触发超时。
- 解法：插件配置 `cwd` 指向固定工作区；`tool-fs-search` 的 `timeoutMs` 调到 180000；
  同时 `sampleOverCapGlobResults: false`。

## 2. 工具失败把 `❌ 工具 xxx 执行失败` 卡片发到群里

- 现象：任何工具异常都会作为卡片推送到 QQ，体验很差。
- 解法：`dist/transport/tool-presenter.js` 里遇到 `data.error` 直接返回 `null`（不渲染卡片），
  让模型改用自然语言解释失败原因。

## 3. 一句话 @ 多个人时出现"名字空空的"

- 现象：`@A @B 你们看` 被 QQ 剥掉了 mention 文本，模型看到的是空白。
- 原因：QQ 的 `content` 不包含被 @ 者的昵称（`<@id>` 标记也没有）。
- 解法：在 `dist/gateway/middleware-setup.js` 加一个 transform：把内容里的 mention id
  映射回昵称（`@昵称`），并在末尾追加「（本条 @ 了：…）」；历史消息里同样处理。

## 4. 主动消息触发 session 格式错误

- 现象：机器人主动发消息时报 `format v4 message requires a producer-owned source kind`。
- 原因：主动消息由插件构造，`source.kind: 'plugin'` 不被会话格式接受。
- 解法：构造消息时用 `source: { kind: 'user' }`。

## 5. 机器人半夜"失联"

- 现象：01:22 之后到 07:07 没有任何响应，进程还在。
- 原因：一次卡住的 turn 占住了串行的 `whenIdle`，后面的消息全部排队等死。
- 解法：`dist/transport/inbound.js` 的 `whenIdle` 加 90 秒超时兜底，超时后继续处理后续消息。

## 6. 重启后记忆永远不整理

- 现象：日志里只有 `memory-distill-start`，没有结果；重启后长时间不触发。
- 原因：两个叠加：
  1. 压缩输出被推理吃光（`finish: max-tokens` / 空正文）——见 02 文档；
  2. 重启后如果群里没人说话，内存里没有群列表，定时器遍历空表。
- 解法：给压缩调用 `reasoningEffort: 'low'` + 增大输出上限；启动时从磁盘扫描所有群记忆；
  同群并发保护；硬超时兜底；所有失败路径落 `debug.jsonl`。

## 7. 判断器"永远是空"

- 现象：`interest`/`invited` 从不生效，所有候选消息都 skip。
- 原因：与记忆相同，推理吃光输出 → JSON 解析失败 → 返回 null。
- 解法：`reasoningEffort: 'low'`、输出上限 800、失败记录原始输出。

## 8. 起床提醒不触发

- 现象：用户说"下午一点四十叫我起床"，没有回应，到点也没提醒。
- 原因：三条叠加：
  1. 没点名/@ 机器人 → 被判断器当闲聊跳过；
  2. 解析只认阿拉伯数字，"一点四十"和"下午"解析不了；
  3. 重启后如果没人说话，有提醒的群不在状态表里，巡检遍历不到。
- 解法：把中文数字/时段纳入解析；提醒持久化并在巡检时主动加载有提醒的群；
  提醒识别限定在点名消息（正常聊天不会这么说）。

## 9. 平台限制备忘

- QQ 公域机器人：群里默认只收到 @ 它的消息，需要群主开启「接收全部群消息」才能旁观；
- 换机器人（appId 变化）后，同一用户的 `member_openid` 会变，人记忆无法延续；
- 群主动消息官方限额 1000 条/天，本方案另有 `dailyMax`。
